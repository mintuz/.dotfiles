# Repository Guidelines

## Project Structure & Module Organization

This repository stores personal dotfiles as GNU Stow packages. Each top-level package mirrors the path it should create under `$HOME`.

- `zsh/` contains shell startup files such as `.zshrc` and `.zsh_profile`. They add a Homebrew-layout prefix (`/opt/homebrew` or `/home/linuxbrew/.linuxbrew`) when present, `PNPM_HOME`, and `mise activate zsh` when `mise` is on `PATH` or in `~/.local/bin`. They do not need the `brew` executable, and optional commands are skipped when missing.
- `mise/.config/mise/conf.d/dotfiles.toml` makes `.nvmrc` and `.node-version` select Node. When a project needs a Node version that is not installed, mise installs it the first time a Node command runs in that project. This needs an existing mise-managed Node, because that installation provides the `node` shim, and mise's default auto-install settings.
- `rex/.config/rex/` contains the configuration of Rex, a terminal multiplexer. Rex reads `init.lua`, which loads `worktrees.lua`, `open-in.lua`, `lazygit-panel.lua` and `agents.lua`. These files share the functions in `helpers.lua`. `open-in.lua` defines **Open in Cursor** (Option+Command+O), which opens the repository of the focused pane in Cursor. Outside a repository, it opens the folder of the pane. `lazygit-panel.lua` defines **Open Lazygit in Floating Pane** (Option+Command+G), which opens lazygit in the folder of the focused pane in a floating pane. `worktrees.lua` defines the actions **New Session in Worktree…** (Option+Command+N), **New Tab in Worktree…** (Option+Command+T) and **Remove Worktree…**. **New Tab in Worktree…** opens the tab in the current session. **New worktree…** is the first row of the checkout picker. Its name field starts with `<project>-<6 random characters>`, for example `dotfiles-k3x9qa`. Press Return to keep the name, or edit it. **Remove Worktree…** lets you tick several worktrees, or **All worktrees**. It removes each worktree that git allows, lists the others, and also deletes each branch that `git branch -d` allows, which is a branch with no unmerged commits. **Remove Merged Worktrees…** lists, already ticked, each worktree that has no changed files and whose branch is merged into HEAD of the main checkout. Untick the worktrees to keep. `rex do worktree_prune project=<path> all=true` removes them all without a prompt. `worktrees.lua` also defines **Close Tab…** (Option+Command+W, in place of Rex's Close Tab). When the focused pane is in a worktree under `~/.rex/worktrees`, it asks whether to remove the worktree before it closes the tab. `init.lua` starts `worktree-watch.lua` with `rex do --all` when it is not already running. After the last tab with a pane in such a worktree closes, for example from the tab's close button, the script runs the `worktree_closed` action, which asks whether to remove the worktree. Git refuses to remove a worktree that has changed or untracked files. The pickers of these actions need a Rex server with control API revision 17 or later. On an older server, give the `project` and `branch` arguments to `rex do`. `agents.lua` defines **Restore Agents…** (Option+Command+R). After a Rex server restart, it resumes the conversations of the Claude Code, Codex, omp and Antigravity (`agy`) panes that Rex restored as shells. `agent-session.sh` records each agent pane in `~/.local/state/rex-agents/<block>.json`. The SessionStart and SessionEnd hooks of Claude Code, the SessionStart hooks of Codex and Antigravity, and `omp/.omp/agent/extensions/rex-tab-title.ts` run the script. The action lists only panes that are idle shells. Run `rex config reload` after you change these files, because Rex does not watch them. `agent-tab-title.sh` copies the terminal title of an agent's pane to the Rex tab that holds the pane. Claude Code, Codex, omp and Antigravity set this title to a short summary of the session. The Stop hooks of Claude Code, Codex and Antigravity run the script, and `omp/.omp/agent/extensions/rex-tab-title.ts` runs it when an omp run ends. Codex runs the hook only after you trust it in Codex.
- `pnpm/.config/pnpm/config.yaml` defines global pnpm security and install policy defaults.
- `agents/.agents/` contains agent skill bundles, references, eval fixtures, `.skill-lock.json`, and `agents/`, the single copy of each subagent definition that more than one harness uses.
- `claude/.claude/CLAUDE.md` contains global Claude Code instructions. `claude/.claude/agents/` holds the Claude Code subagents: relative symlinks to the shared copies in `agents/.agents/agents/`. `~/.claude` is the personal Claude Code profile, which `claude` uses.
- `workclaude/.workclaude/` is the work Claude Code profile. The `workclaude` alias in `zsh/.zshrc` runs `claude` with `CLAUDE_CONFIG_DIR=~/.workclaude`. The package contains only relative symlinks to the shared `CLAUDE.md` and subagents. Each profile keeps its own login, `settings.json`, plugins, MCP servers and history in its local directory. Do not add these files to this repository.
- `omp/.omp/agent/config.yml` contains global omp (oh-my-pi) settings. `omp/.omp/agent/agents/` holds the omp subagents: omp-only files such as `astra.md` and `fable.md`, and relative symlinks to the shared copies. `omp/.omp/agent/extensions/` holds omp extensions. omp databases, sessions, caches and the runtime `config.yml.lock` stay local.
- `antigravity/.gemini/config/` contains global Antigravity lifecycle hooks (`hooks.json`), the peon-ping adapter (`peon-hook.sh`), `skills.json` (which registers `~/.agents/skills`), and global writing-style rules (`AGENTS.md`, without Claude's `@RTK.md`). `hooks.json` wires `peon-hook.sh` to `SessionStart`, `PostToolUse` (`run_command`), and `Stop` (reusing the Claude Code peon-ping installation, config, and J.A.R.V.I.S. pack), and wires Rex's `agent-session.sh agy` (`SessionStart`) and `agent-tab-title.sh` (`Stop`). Antigravity's `config.json`, `mcp_config.json`, installed plugins, CLI settings, and runtime state stay local.
- `.githooks/pre-push` runs `gitleaks` on the commits that a push sends, and stops the push when it finds a possible secret. When `gitleaks` is not installed, the hook stops every push. `install.sh` sets `core.hooksPath` to `.githooks` for this repository only.
- `install.sh` moves a real `~/.zshrc`, a real `~/.omp/agent/config.yml`, a real `~/.config/rex/init.lua`, real Antigravity files that this repository manages (`~/.gemini/config/{hooks.json,peon-hook.sh,skills.json,AGENTS.md}`), real agent files that this repository manages, and `~/.agents` files that conflict with this repository into a new `~/.dotfiles-backup.XXXXXX` directory. Each run that backs up files creates its own directory, so a run never overwrites an earlier backup. The installer then creates `~/.omp/agent`, `~/.omp/agent/agents`, `~/.omp/agent/extensions`, `~/.claude/agents`, `~/.workclaude/agents`, `~/.config/mise/conf.d`, `~/.config/rex` and `~/.gemini/config` as real directories and runs `stow --target="$HOME" zsh agents pnpm claude workclaude omp mise rex antigravity`. When `rtk` is on `PATH`, the installer then runs `rtk init --global --auto-patch` once for `~/.claude` and once for `~/.workclaude`, and `rtk init --global --agent antigravity --auto-patch` to install the RTK plugin into `~/.gemini/config/plugins/rtk`. RTK writes `RTK.md` and its hook into each local Claude profile directory. The shared `CLAUDE.md` imports `@RTK.md`. When `jq` is on `PATH`, the installer then adds a Stop hook that runs `~/.config/rex/agent-tab-title.sh`, and SessionStart and SessionEnd hooks that run `~/.config/rex/agent-session.sh claude`, to `~/.claude/settings.json` and `~/.workclaude/settings.json`. When `~/.codex` exists, it also adds the Stop hook and a SessionStart hook that runs `agent-session.sh codex` to `~/.codex/hooks.json`. A file that already has a hook keeps it unchanged. The installer also merges the managed Antigravity MCP servers into `~/.gemini/config/mcp_config.json`, always adding the four portable remote HTTP servers (`notion`, `mobbin`, `revenuecat`, `tally`), adding `talat` and `2do` only when their binaries exist on the machine (resolving `$HOME` for `2do`), and preserving any extra local servers. When `agy` is on `PATH`, the installer clones `https://github.com/mintuz/skills.git` (falling back to `~/.claude/plugins/marketplaces/mintuz-skills` when offline) and runs `agy plugin install` for each plugin in its marketplace manifest; when the sync fails, it prints a message and continues. When `peon-ping-setup` is on `PATH`, the installer then runs `peon-ping-setup --packs=jarvis-mk2` , `peon packs use jarvis-mk2` and `peon notifications off` once for `~/.claude` and once for `~/.workclaude`. peon-ping plays sounds when an agent session starts, finishes or needs input. `peon notifications off` stops its desktop pop-ups, and the sounds still play. The setup writes its hooks, skills and `config.json` into each local profile directory, and the J.A.R.V.I.S. pack into `~/.openpeon/packs`. `mac-dev-machine-setup` installs peon-ping from Homebrew. When the setup fails, for example without a network, the installer prints a message and continues.

Tools and `install.sh` can update files in this checkout through Stow links, for example through the folded `~/.agents` link. The owner wants this behaviour. Do not report these writes as defects, and do not add guards against them.

Avoid committing machine-local files such as `.DS_Store`, temporary editor files, or secrets.

## Build, Test, and Development Commands

- `./install.sh` installs the managed packages into `$HOME` using Stow. Run only when you intend to update live dotfile symlinks.
- `stow --simulate --verbose zsh agents pnpm claude workclaude omp mise rex antigravity` previews symlink changes without modifying `$HOME`.
- `stow --restow zsh agents pnpm claude workclaude omp mise rex antigravity` refreshes existing symlinks after package changes.
- `zsh -n zsh/.zshrc zsh/.zsh_profile` checks shell files for syntax errors.
- `bats tests` runs the installer tests against a temporary home directory, the pre-push hook tests against a temporary remote, the Rex tab title and agent session hook tests, and the Rex action tests. The Rex action tests are skipped when `rex` is not installed. Install bats-core first, for example with `brew install bats-core`.
- `gitleaks git --no-banner --redact .` scans the full history. Install gitleaks first, for example with `brew install gitleaks`. Old history contains false positives, such as placeholder keys in skill references and files from a removed `atom/` folder.
- `git status --short` confirms the final change set before committing.

## Coding Style & Naming Conventions

Shell files use POSIX-compatible syntax where practical, with zsh-specific features only when needed. Keep indentation at two spaces inside functions and conditionals, preserve existing alias style, and quote variables when paths or user input may contain spaces. Dotfile package paths should match their destination exactly, for example `zsh/.zshrc` maps to `~/.zshrc`.

Agent skills live under `agents/.agents/skills/<skill-name>/`. Use lowercase kebab-case for skill directory names and keep primary instructions in `SKILL.md`.

To share a subagent between Claude Code and omp, put the file in `agents/.agents/agents/<name>.md`, then add a relative symlink to it in `claude/.claude/agents/`, `workclaude/.workclaude/agents/` and `omp/.omp/agent/agents/`. A subagent with harness-specific frontmatter, such as an omp model selector, goes only in that harness's package. Codex has no subagent folder; skills that need a delegate use its general-purpose agent.

## Testing Guidelines

`tests/install.bats` tests `install.sh` with bats-core. Run `bats tests` after you change `install.sh`. Validate other changes with syntax checks and Stow dry runs before installing. For agent skill changes, inspect related `evals/evals.json` files when present and keep examples or fixtures close to the skill they exercise.

## Commit & Pull Request Guidelines

Recent history uses short, imperative commit subjects, sometimes with a Conventional Commit prefix such as `feat:`. Keep subjects concise, for example `feat: add zsh alias` or `pnpm security defaults`.

Pull requests should explain the affected package, note any manual verification commands run, and call out changes that affect shell startup, package manager policy, or agent behavior. Include screenshots only when a change affects a visual or rendered artifact.

## Security & Configuration Tips

Do not commit tokens, private hostnames, or work-only configuration. Keep personal or employer-specific overrides in local files sourced conditionally, such as `~/.zsh_work_profile`.
